# AEGIS-IPsec: Encrypted Traffic Analysis & Prediction
## Frontend Architecture & System Documentation

This document provides a comprehensive overview of the frontend foundation built for the **IPsec Encrypted Traffic Analysis & Prediction** web application.

---

## 1. Project Overview & Architecture Principles

The application is architected as a SOC (Security Operations Center) / Network Security Intelligence platform designed to interface with a Docker-based strongSwan VPN testbed running on WSL/Linux.

### Core Architectural Decisions:
1. **Clean Separation of Concerns**:
   - The browser UI **never** invokes Docker commands, strongSwan, tcpdump, or shell utilities directly.
   - All network telemetry, packet dissections, and container states sit behind an API/Service abstraction layer.
2. **Pluggable Mock & Live Backend Mode**:
   - `src/api/client.ts` supports toggling between high-fidelity mock datasets and future live REST/WebSocket APIs with a single configuration flag (`VITE_USE_MOCKS=true/false`).
3. **Preserved Working strongSwan Lab Topology**:
   - Nodes:
     - `vpn-client` (IPv4: `10.10.0.10`, IPv6: `fd00:10:10::10`)
     - `vpn-server` (IPv4: `10.10.0.20`, IPv6: `fd00:10:10::20`)
     - `traffic-generator` (IPv4: `10.10.0.30`, IPv6: `fd00:10:10::30`)
     - `passive-tap` (IPv4: `10.10.0.254` - PCAP sensor / defensive monitoring demo node only)
   - Working VPN Proposal (Default):
     - **IKEv2**: `AES256-SHA256-MODP2048`
     - **ESP**: `AES256-GCM16`
     - **Authentication**: Pre-Shared Key (PSK)
     - **Traffic Selectors**: `10.10.0.10/32` &harr; `10.10.0.20/32`
4. **Backend-Driven Packet Dissection**:
   - The UI does not attempt to parse raw binary PCAP files in Javascript. It visualizes structured packet dissections (Frame, Ethernet, IPv4, ESP, IKEv2) generated by backend TShark/tcpdump workers.

## 3. Dedicated Views Summary (11 Pages)

| Page | Key Features & Responsibilities |
| :--- | :--- |
| **1. Dashboard** | High-level SOC view with metric cards (Tunnel state, Throughput, AI accuracy, Security grade), live wire throughput chart, protocol distribution donut, active SA details, and recent ML inferences. |
| **2. VPN Lab** | Interactive topology canvas displaying `vpn-client` (10.10.0.10), `vpn-server` (10.10.0.20), `traffic-generator` (10.10.0.30), and conceptual `passive-tap` (10.10.0.254). Shows animated ESP tunnel with SPIs, container CPU/RAM telemetry, raw `statusall` terminal, and tunnel renegotiation. |
| **3. VPN Configuration** | Preserves working lab configuration (`AES256-SHA256-MODP2048` + `AES256-GCM16` + PSK) while offering selectable alternatives (ChaCha20, ECP384). Includes full syntax `/etc/swanctl/conf.d/ipsec-lab.conf` editor with save/revert actions. |
| **4. Traffic Generator** | Controls for running synthetic workloads (iPerf3 TCP bulk, UDP bursts, VoIP G.711 RTP, HTTPS surf). Displays active sessions, throughput rate, transmitted bytes, and CLI invocation previews. |
| **5. Packet Capture** | Manages interface capture (`eth0`, `xfrm0`), BPF filters (`esp or udp port 500 or udp port 4500`), kernel ring buffer status, and stores PCAP recordings with size and packet counts. |
| **6. Packet Analysis** | Wireshark-inspired 3-pane dissector: packet list with ESP SPIs, collapsible TShark parsed protocol layer tree, and 16-byte raw hex/ASCII payload stream with copy-to-clipboard. |
| **7. Feature Extraction** | Computes flow statistical vectors for encrypted streams (Shannon entropy, mean packet length, variance, inter-arrival time, forward/backward ratio) and displays packet size distribution histograms. |
| **8. AI Prediction** | Real-time classification of encrypted traffic into application classes (File Transfer, VoIP, Web Browsing, Video Streaming) with confidence %, inference latency, multiclass probability distribution, and SHAP feature importance. |
| **9. Security Assessment** | NIST/BSI cryptographic posture assessment (Grade A, 94/100). Details cipher strengths (AES-256-GCM), PFS key exchange (MODP2048), anti-replay protection (64 packets), and hardening recommendations. |
| **10. Logs** | Terminal log viewer streaming strongSwan charon daemon logs, Linux XFRM netlink events, tcpdump packet events, and ML inferences. Includes search, level filtering, auto-scroll, and JSON export. |
| **11. Settings** | Configuration for future backend REST API endpoint (`http://localhost:8000`), request timeout, live/mock mode toggle, and read-only Docker container network parameters. |

## 4. How to Run the Frontend

### Prerequisites:
- Node.js &ge; 18 (Tested on Node v22.12.0)
- npm &ge; 9 (Tested on npm 11.6.2)

### Commands:

1. **Install Dependencies** (already installed in workspace):
   ```bash
   npm install
   ```

2. **Run Type Check (TypeScript)**:
   ```bash
   npx tsc --noEmit
   ```

3. **Build Production Bundle**:
   ```bash
   npm run build
   ```

4. **Start Development Server**:
   ```bash
   npx vite --host 127.0.0.1 --port 5173
   ```
   Open your browser to: `http://localhost:5173/` (or `http://127.0.0.1:5173/`).

## 5. Transitioning from Mock Services to Live Backend

All data flows through typed functions in `src/services/` that delegate to `apiClient` (`src/api/client.ts`). When the backend is ready:

1. In `src/api/endpoints.ts` or via the **Settings** page:
   - Point `baseUrl` to your backend (e.g. `http://localhost:8000`).
   - Flip `useMock` to `false` (or set `VITE_USE_MOCKS=false` in `.env`).

### Services and Their Corresponding Future Backend API Endpoints:

| Frontend Service Method | Replaces Mock With Live Backend Endpoint | Expected Backend Action in Docker Lab |
| :--- | :--- | :--- |
| `vpnService.getVPNStatus()` | `GET /api/vpn/status` | Queries strongSwan `swanctl --stats` / `/proc/net/xfrm_stat` in `vpn-client` container. |
| `vpnService.getVPNConnections()` | `GET /api/vpn/connections` | Executes `swanctl --list-sas` to extract active IKE_SA & CHILD_SA SPIs, cipher, and byte counts. |
| `vpnService.getVPNConfiguration()` | `GET /api/vpn/config` | Reads `/etc/swanctl/conf.d/ipsec-lab.conf` from `vpn-client`. |
| `vpnService.updateVPNConfiguration()` | `POST /api/vpn/config` | Writes updated config and executes `swanctl --load-all --reload-settings`. |
| `vpnService.restartVPNTunnel()` | `POST /api/vpn/restart` | Executes `swanctl --terminate --ike lab-tunnel && swanctl --initiate --child net-net`. |
| `trafficService.startTrafficSession()` | `POST /api/traffic/start` | Spawns `iperf3 -c 10.10.0.20` inside `traffic-generator` container. |
| `trafficService.stopTrafficSession()` | `POST /api/traffic/stop` | Terminates active iPerf3 or synthetic traffic process. |
| `packetService.startCapture()` | `POST /api/packets/start-capture` | Starts `tcpdump -i eth0 -w /captures/...` on the monitoring container/tap. |
| `packetService.stopCapture()` | `POST /api/packets/stop-capture` | Stops `tcpdump`, runs `tshark -r <file> -T json` to extract packet layers, and indexes the PCAP. |
| `packetService.getPackets()` | `GET /api/packets?pcapId=...` | Returns parsed TShark JSON frame structure with layer breakdown and hex representation. |
| `aiService.getFeatures()` | `GET /api/ai/features` | Backend feature extractor parses flow packet length/time distributions. |
| `aiService.getPredictions()` | `GET /api/ai/predictions` | Backend ML model (XGBoost/PyTorch) runs inference on extracted flow features. |
| `securityService.getSecurityAssessment()`| `GET /api/security/assessment` | Audits negotiated IKE/ESP ciphers against cryptographic compliance policies. |
| `logService.getLogs()` | `GET /api/logs` | Tails `/var/log/charon.log` and kernel `dmesg \| grep -i xfrm`. |
